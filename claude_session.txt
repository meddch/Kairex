  WHAT TO BUILD:                                                                
  Two endpoints:                                                                
  - POST /extract-session — receives a raw conversation transcript, extracts    
  structured organizational facts using an LLM, stores them in PENDING state    
  (not auto-committed), writes a durable checkpoint after each fact             
  - GET /inject-context?org_id=X — reads APPROVED facts for that org from DB,   
  passes them to a second LLM call, returns a prompt-ready context block in     
  French                                                                        
                                                                                
  THREE HARD REQUIREMENTS (non-negotiable):                                     
  1. Human Approval Gate: facts must go pending → approved/rejected →           
  committed. Never auto-commit. Pending state must survive server restarts. Add 
   POST /facts/{id}/approve and POST /facts/{id}/reject endpoints. Add GET      
  /facts/pending to list them.                                                  
  2. Idempotent Checkpoints: write a durable checkpoint to DB after each fact   
  is processed. If the job crashes midway, re-running resumes from last         
  checkpoint. Same input = same output, no duplicate facts.                     
  3. Two independent agents, no shared context: ExtractorAgent reads transcript 
   → produces facts. WriterAgent reads fact store → produces context block.     
  They do NOT share state. Only the database connects them. You must be able to 
   swap one without touching the other.                                         
                                                                                
  STACK:                                                                        
  - Python + FastAPI                                                            
  - SQLite with WAL mode (durable, no setup, persists across restarts)          
  - OpenAI gpt-4o-mini for both agents (cheap, fast)                            
  - Plain OpenAI SDK — no LangChain, no LangGraph                               
  - Deployed on Railway

     ---
     Implementation Plan

     1. database.py

     - init_db() — creates all three tables with WAL mode pragma
     - get_db() — yields a sqlite3 connection (WAL mode on every connection)
     - Tables:
       - sessions(id TEXT PK, org_id, transcript, status, created_at)
       - facts(id TEXT PK, session_id, org_id, entity_type, entity_value, 
     attribute, value, confidence REAL, status TEXT DEFAULT 'pending', 
     source_snippet, created_at)
       - checkpoints(id TEXT PK, session_id, fact_index INT, fact_data TEXT, 
     status TEXT, created_at) UNIQUE(session_id, fact_index)
     - Use uuid4() for all IDs, datetime.utcnow().isoformat() for timestamps

     2. agents/extractor.py — ExtractorAgent

     - ExtractorAgent(api_key: str)
     - extract(transcript: str, session_id: str, org_id: str, db_conn) -> 
     list[dict]
     - System prompt instructs gpt-4o-mini to return a JSON array of facts:
     [{"entity_type": "...", "entity_value": "...", "attribute": "...", "value":
      "...",
       "confidence": 0.9, "source_snippet": "..."}]
     - Idempotency: Before inserting each fact, check checkpoints for existing
     (session_id, fact_index). If found and status=done, skip insertion and use
     stored fact_data.
     - After each fact: INSERT OR IGNORE INTO checkpoints → then INSERT OR 
     IGNORE INTO facts.
     - Facts inserted with status='pending' — never auto-committed.
     - Returns list of inserted/resumed fact dicts.

     3. agents/writer.py — WriterAgent

     - WriterAgent(api_key: str)
     - generate_context(org_id: str, facts: list[dict]) -> str
     - System prompt instructs gpt-4o-mini to synthesize approved facts into a
     French prompt-ready context block.
     - Input: list of approved fact dicts (entity_type, entity_value, attribute,
      value).
     - Output: plain string — the context block in French.
     - No DB access — facts are passed in, not read by the agent itself.

     4. main.py

     FastAPI app with lifespan that calls init_db() on startup.

     Endpoints:

     POST /extract-session
     - Body: {"org_id": str, "transcript": str}
     - Creates a session row, instantiates ExtractorAgent, calls extract().
     - Returns {"session_id": ..., "facts_extracted": N, "facts": [...]}

     GET /inject-context?org_id=X
     - Queries facts WHERE org_id=X AND status='approved'.
     - If none, returns 404 with message.
     - Instantiates WriterAgent, calls generate_context(org_id, facts).
     - Returns {"org_id": ..., "context_block": "...", "facts_used": N}

     GET /facts/pending
     - Optional query param ?org_id=X.
     - Returns all facts with status='pending', optionally filtered by org_id.

     POST /facts/{id}/approve
     - Sets facts.status = 'approved' where id matches.
     - Returns updated fact or 404.

     POST /facts/{id}/reject
     - Sets facts.status = 'rejected' where id matches.
     - Returns updated fact or 404.

     5. requirements.txt

     fastapi
     uvicorn[standard]
     openai
     python-dotenv

       "build": {"builder": "NIXPACKS"},

     }
